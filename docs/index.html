Data architecture

Consent ≠ data access

Understand how the layers are separated.

01

Consent registry

Structured, versioned evidence: participant ID, dataset scope, purpose, decision, form version, timestamp and withdrawal history.

02

Permission engine

Deterministic check of the exact participant, dataset and purpose. Missing grant defaults to DENY.

03

Data repository & release

A separately governed service selects, protects and releases data under authorization. This prototype does not implement delivery.

Illustrative permission flow

1 · Request

Researcher states dataset, purpose, scope and plain-language explanation.

2 · Choice

Participant decides. Research and model-training choices remain distinct.

3 · Check

Permission engine verifies current, exact-scope grant.

4 · Governance

Authorization and review controls apply separately.

5 · Release

Controlled repository or workspace handles approved data.

6 · Trace

Access and decisions are logged and reviewed.

Conceptual architecture—not a claim that each layer is implemented in this web demo.
