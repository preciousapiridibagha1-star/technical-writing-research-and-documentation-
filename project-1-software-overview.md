# Project 1: Software Overview — Cloud-Based AI Assistants (Category-Level Sample)

**Document type:** General software-category overview.  
**Audience:** Non-technical professionals, small organisations and knowledge workers evaluating AI assistance.  
**Scope:** This describes a category, not one vendor's product or a verified implementation.

## Product category

Cloud-based AI assistants are software services that accept user instructions and return generated or transformed outputs. Depending on the service, a user may interact through a website, mobile application or API. The provider may operate the model and some supporting infrastructure remotely.

Capabilities differ across providers, models, account plans and regions. Common use cases include drafting, rewriting, summarisation, explanation, brainstorming and assistance with structured information. These are possible use cases, not guaranteed features of every service.

## Intended users and common tasks

| User group | Example task | Required human check |
|---|---|---|
| Administrative and business professionals | Draft or restructure routine documents | Confirm names, dates, commitments and tone |
| Researchers and analysts | Generate an outline or summarise supplied material | Verify claims and citations against original sources |
| Writers and editors | Explore structure or revise clarity | Check factual accuracy, voice and rights |
| Small organisations | Prepare internal templates or customer-response drafts | Check policy, privacy and approval requirements |
| Technical teams | Explain code or draft documentation | Test technical instructions and review code before use |

## Typical interaction pattern

1. The user enters an instruction and, where supported, supplies context or files.
2. The service processes the request using its configured model and tools.
3. The assistant returns a response or proposed output.
4. The user reviews, corrects and decides whether to use it.

A generated response is not automatically verified, approved or suitable for external publication.

## Evaluation criteria

Before selecting a named service, check: model and feature availability; supported countries and devices; price and usage limits; data retention and training terms; account permissions; accessibility; integration support; export and deletion options; and support arrangements.

## Important limitations

- Output quality varies by task, prompt, model and source material.
- The service may generate inaccurate or outdated information.
- Security, privacy and retention controls differ by provider and plan.
- Internet access is generally needed for cloud-hosted processing.
- API access and third-party integrations are not universal.
- Use of the service does not remove the need for human review and organisational approval.

## Evidence and limitations

This is an illustrative category overview. No named platform was tested, and the document makes no claim that all services share the listed capabilities. Product-specific claims require a named provider, dated official sources and verification of the relevant plan and region.

**Portfolio purpose:** Demonstrates how to define a software category, identify user groups, connect features to tasks and state evidence boundaries.
