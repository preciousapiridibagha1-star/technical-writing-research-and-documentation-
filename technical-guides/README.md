# Technical Writing and Documentation Samples

This section demonstrates how technical information can be structured for different audiences.

## Sample types

- **README guides:** explain a project's purpose, prerequisites, setup, use and support.
- **FAQs:** answer common user questions directly and consistently.
- **User guides:** explain tasks in the order a user performs them.
- **Documentation reviews:** identify ambiguity, missing prerequisites, broken sequences and unsupported claims.

## Documentation principles

- Write for a defined audience and task.
- Put the most important information first.
- Use consistent terminology.
- Explain prerequisites before instructions.
- Number steps when sequence matters.
- Distinguish required actions from optional recommendations.
- Include expected results and recovery guidance.
- Mark version, date and known limitations.
- Do not claim instructions have been tested unless they have been followed in a suitable environment.

Samples may use hypothetical systems to demonstrate writing structure. They must be labelled as illustrative and must not be mistaken for documentation of a deployed product.
