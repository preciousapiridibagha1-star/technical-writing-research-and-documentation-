# Development Roadmap

## Guiding approach

Develop the project in stages. Validate the problem and user workflow before expanding the technical scope. The full product vision is broader than the first demonstration.

## Stage 1: Research and validation
- Review competing platforms and their current capabilities.
- Identify the specific workflows they serve well.
- Examine the needs of public health organisations, health organisations and education organisations.
- Speak with potential users where access is available.
- Test whether fragmented programme information and reporting are significant problems for the intended users.
- Record evidence, assumptions and unresolved questions.

**Output:** validated problem statement, user profiles and prioritised use case.

## Stage 2: Product definition
- Finalise core workflows.
- Define common programme, activity, indicator and evidence fields.
- Define what varies across the three initial sector configurations.
- Agree the demonstration acceptance criteria.
- Document privacy and safety boundaries.

**Output:** requirements and prototype-ready workflow specification.

## Stage 3: Interface and data design
- Create dashboard and navigation.
- Design forms and import review.
- Design programme and indicator views.
- Design AI question and report preview.
- Define the minimal data model.

**Output:** clickable interface prototype and data model.

## Stage 4: Build the demonstration
- Implement the Data Hub workflow.
- Implement programme and activity monitoring.
- Implement deterministic indicator calculations.
- Implement a limited AI-assisted question and reporting workflow.
- Configure Public Health, Health Organisation and Education sample scenarios.

**Output:** limited working demonstration using synthetic data.

## Stage 5: Testing and refinement
- Test import behaviour and validation.
- Check calculation accuracy.
- Test AI answers against known sample records.
- Test unsupported questions and missing-data cases.
- Review usability with a small number of testers if available.
- Document limitations and unresolved risks.

**Output:** tested demonstration and evaluation notes.

## Stage 6: Presentation and future plan
- Prepare a concise product walkthrough.
- Show one end-to-end workflow.
- Explain the three sector scenarios.
- Present what is implemented versus planned.
- Present the future development path and resource requirements.

**Output:** demonstration, documentation and a realistic next-stage plan.

## Development roles

The project lead owns the problem framing, product direction, research, requirements, documentation and demonstration narrative.

Technical collaborators may be needed for:
- Frontend implementation.
- Backend and database engineering.
- AI integration and retrieval.
- Security and privacy review.
- Testing and deployment.

The project does not assume the project lead will personally implement every engineering component.

## Scope control

Do not add a new feature simply because it is technically possible. Prioritise features that prove the core value: bringing programme information together, monitoring delivery and producing traceable insights and reports.
